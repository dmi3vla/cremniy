# Прототип визуальных связей

Этот каталог — небольшая воспроизводимая C++17-фикстура для экрана **Canvas → Trace…**. Также экран можно открыть напрямую:

```bash
./build/cremniy --trace-prototype fixtures/trace/trace-manifest.json
```

Нужны Qt 6.8.3, C++17, Python 3, Git, GCC/G++ и GNU binutils (`nm`, `readelf`, `objdump`, `addr2line`). Для пересборки данных из корня репозитория:

```bash
python3 fixtures/trace/build_fixture.py
cmake -S src -B build -DQt6_DIR="$PWD/qt-6.8.3-install/lib/cmake/Qt6"
cmake --build build --parallel 2
cmake -S tests -B tests/build -DQt6_DIR="$PWD/qt-6.8.3-install/lib/cmake/Qt6"
cmake --build tests/build --parallel 2
ctest --test-dir tests/build --output-on-failure
```

Если Qt установлена в другом месте, задайте свой `Qt6_DIR`. Генератор собирает `base/head` с `-O0 -g` и `-O2 -g`, а также один `head -O2` без отладочной информации. Используются `-std=c++17 -fno-pie -no-pie`. Полная версия компилятора, архитектура, флаги, SHA-256 исходника и ELF записаны для каждой сборки в `trace-manifest.json`. Идентификатор сборки включает ревизию, режим и часть SHA-256 бинарника.

## Состав свидетельств

- `base/demo.cpp` и `head/demo.cpp` — исходные ревизии. В `head` меняется `scenario_two`: добавляется вызов `shared_helper`.
- `base-head.diff` создан командой `git diff --no-index -- base/demo.cpp head/demo.cpp`.
- `artifacts/demo-*` — настоящие ELF-файлы, `artifacts/demo-*.objdump.txt` — сохранённый вывод `objdump -d -M intel`.
- `trace.codemap.txt` — две трассы существующей модели Codemap. Один `shared_helper` присутствует в обеих как два отображения одной идентичности.
- `trace-manifest.json` — связи, метаданные сборок и диапазоны. Адреса берутся из `nm`/`readelf` и инструкций `objdump`; строки — из DWARF через `addr2line`. Диапазон функции определяется размером символа из `nm`, а не соседством адресов.
- `artifacts/trace-explorer.png` — снимок интерфейса из Qt-теста. Достоверность соответствий проверяется отдельными тестами и хешами.

## Правила сравнения

В этой среде нет установленного `clang`/libclang или Tree-sitter C++; анализатор фикстуры **не является полноценным AST-парсером**. Он извлекает простые определения функций из этой контролируемой фикстуры и балансирует фигурные скобки. Для точного совпадения сравниваются токены тела без пробелов. Для ограниченного структурного сравнения имена параметров и локальных переменных заменяются по порядку объявления на `v0`, `v1` и т. д. Числа, типы, условия, имена вызовов и записи в глобальное состояние сохраняются. Кандидаты должны иметь одинаковые списки вызовов, констант, условий и типов, а сходство последовательностей токенов — не ниже 0,85. Дополнительная запись `state` показывается как различие.

Группы означают только основание для сравнения. Узлы не объединяются, а сходство кода не объявляется доказательством одинакового поведения. Простая лексическая обработка не охватывает макросы, шаблоны, перегрузки, вложенные лямбды, семантику типов и алиасинг. На произвольном C++ проекте требуются полноценный парсер и более строгая идентификация символов.

## Связи и сохранение

`requirement-symbol` и `requirement-source` заданы человеком в фикстуре; `calls` также проверены вручную. `source-instruction` извлечены инструментами и привязаны к ревизии исходника, SHA-256, сборке и секции. Поля `originKind` (`human`, `tool`, `model`) и `origin` хранят категорию и подробность происхождения; модельные предложения в этом прототипе не создаются. Один символ может иметь несколько требований, одна строка — несколько диапазонов инструкций, а одинаковый адрес в разных секциях остаётся различимым.

Кнопка **Save session** сохраняет связи, группы и выбранную сборку в JSON; **Open manifest** открывает сохранённый файл. Сессия ссылается на исходные свидетельства через `evidenceRoot`, поэтому при переносе каталога нужно обновить этот путь. Если SHA-256 источника или ELF не совпадает, модель сообщает об ошибке и не загружает адреса изменённого ELF как доказательство.

Известные ограничения: `ObjectFileIndexer` для обычных проектов пока требует radare2; на этой машине его нет. Фикстура использует GNU binutils, а существующий `DisassemblerWorker` повторно разбирает ELF через backend `objdump`. Код без DWARF помечается явно. Исчезновение `debug_only` после `-O2` помечается отсутствием подтверждённого диапазона, а не вымышленным адресом. Скриншот сделан в Qt offscreen; ручная проверка кликов мышью в оконном менеджере не проводилась.
